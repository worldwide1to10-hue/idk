**What must *not* be claimed about Bash sandboxing**

- Bash sandboxing (the scoped Read/Edit/Write tools that the benchmark runner provides) is **only an application‑level safeguard**.  
- It **does not give OS‑level isolation** and cannot be said to enforce system‑wide permissions, user‑group policies, or kernel‑enforced access controls.  
- Consequently, one must **not** claim that the Bash sandbox replaces or equates to the operating system’s own shell‑sandbox mechanisms (e.g., seccomp‑BPF, namespace isolation, or Cgroup limits).  
- The runtime’s own documentation makes this clear: *“Filesystem path checks and permission gates are application safeguards. The runtime has no OS‑level shell sandbox.”*  

In short, any assertion that the Bash sandbox provides true OS‑level isolation or that it can be relied upon for system‑wide security is **incorrect** and should be avoided.
